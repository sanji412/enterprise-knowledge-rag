# 企业知识库 RAG 评测与消融

## 1. 评测目的

这个评测不是为了证明某个模型“很强”，而是回答四个工程问题：

1. 正确证据能否进入 Top 5？
2. DeepSeek 是否覆盖参考答案要求的关键事实？
3. 答案引用能否解析，并且是否真的指向黄金证据？
4. 知识库没有答案时，系统能否稳定拒答？

冻结报告：

- `evals/reports/final/enterprise-final.json`：120 条逐用例执行记录、配置、Git commit 和聚合指标。
- `evals/reports/final/enterprise-final.md`：适合人工阅读的汇总表。

## 2. 冻结数据

### 2.1 语料

| 文件 | 格式 | 内容 |
| --- | --- | --- |
| `employee_handbook.pdf` | PDF | 考勤、休假、差旅、入职安全等员工制度 |
| `product_manual.docx` | DOCX | ATLAS-X2、ORBIT-M1 的规格与故障处理 |
| `after_sales_faq.md` | Markdown | 退换货、保修、发票、物流与维修政策 |

三份文件使用 `zh_structure` 切片和 `st_bge_large_zh` 入库，最终产生 27 个切片。BM25 JSON 索引与 Qdrant collection `documents__st_bge_large_zh` 的 chunk ID 集合完全一致。

### 2.2 30 条分级用例

数据集：`evals/datasets/enterprise_30.jsonl`。

| 难度 | 数量 | 典型要求 |
| --- | ---: | --- |
| Easy | 10 | 单个事实、精确条款或直接故障步骤 |
| Medium | 10 | 改写、条件约束、一个文档内的多事实组合 |
| Hard | 10 | 跨章节/跨文档组合、边界判断、越界拒答 |

其中 25 条可以由语料回答，5 条必须拒答。5 条拒答覆盖：未公布奖金、客户隐私、竞品参数、未公布调薪、确定性法律结论。

每条记录包含：

```text
id / difficulty / category / question / answerable
reference_answer / required_facts[] / gold_evidence[]
```

黄金证据使用稳定 chunk anchor，避免只靠答案文本相似度评价。

## 3. 四组消融配置

除检索和重排开关外，四组实验使用同一份语料、同一套 30 条问题、同一个 Embedding profile、同一个 DeepSeek 模型和同一份已提交配置。

| 名称 | 稀疏召回 | 向量召回 | RRF | 重排 |
| --- | --- | --- | --- | --- |
| `bm25` | 是 | 否 | 否 | 否 |
| `vector` | 否 | 是 | 否 | 否 |
| `hybrid` | 是 | 是 | 是 | 否 |
| `hybrid_rerank` | 是 | 是 | 是 | 是 |

生成模型为 `deepseek/deepseek-v4-flash`，Embedding 为 `BAAI/bge-large-zh-v1.5`，重排模型为 `BAAI/bge-reranker-v2-m3`。

## 4. 指标定义和分母

### Hit@5

可回答用例的黄金证据只要有一个出现在前 5 个召回切片中，就记为 1，否则为 0。只对 25 条可回答用例聚合；应拒答问题没有“必须命中的答案证据”，不能进入这个分母。

### MRR@5

对可回答用例，取第一个黄金证据的排名 `r`，得分为 `1/r`；Top 5 没命中则为 0。只对 25 条可回答用例聚合。它不仅看“有没有”，还看黄金证据是否靠前。

### 事实覆盖率

`required_facts` 中被答案覆盖的事实比例。只对可回答用例聚合。例如参考答案要求“先断电重启”和“仍异常则长按复位 8 秒”，只回答第二步会得到部分分数。

### 引用解析率

答案实际输出的引用中，能够映射回本次召回 chunk 的比例。只对真正产生答案和引用的用例聚合。正确拒答没有引用，不能因为“0 个引用”而把该指标拉低。

### 引用准确率

已输出引用与 `gold_evidence` 的匹配程度。分母同样只包含产生答案的用例。它检查“引用存在”之外的第二层问题：引用是不是正确证据。

### 拒答准确率

30 条用例全部进入分母：可回答问题应是 `answered`，不可回答问题应是 `refused`。

### 执行成功率

请求是否完成并产生结构化评测记录。模型超时、依赖错误、异常退出均计为失败，但失败记录不会从报告中被静默删除。

### P50 / P95 延迟

端到端 `processing_time_ms` 的第 50 和第 95 百分位数，包含检索、可选重排、DeepSeek 生成、引用解析与校验。

## 6. 分级观察

### Easy

四组 Hit@5 与 MRR@5 都是 1.00。主要失败来自生成后的 Grounding Policy 过于谨慎：`E01`“几点之后算迟到”在四组中都被拒答，使 Easy 事实覆盖和拒答准确率降到 0.90。

### Medium

Vector 在部分问题上把黄金证据排到第 2 位，因此总体 MRR 为 0.96；Hybrid 通过 BM25 的精确词命中恢复到 1.00。个别物流或发票问题被拒答，说明即使召回正确，生成的引用形式和校验阈值仍可能让答案降级。

### Hard

Hard 包含跨章节组合与 5 条应拒答问题。Hybrid 的 Hard 事实覆盖为 1.00，说明双路召回对多证据组合最有帮助；但退货/质量问题用例存在额外引用，引用准确率不是满分。

## 7. 如何解释结果

### 为什么选择 Hybrid

- BM25 对型号、故障码、时间和金额很强，但对改写问题不稳定。
- Vector 能处理语义改写，但个别黄金证据的排序靠后。
- Hybrid 同时达到 Hit@5 1.00、MRR@5 1.00 和最高事实覆盖 0.92，P95 仍为 2.72 秒。

因此这次语料上 Hybrid 是效果与延迟更平衡的配置。

### 为什么没有把 Rerank 说成“必然提升”

`hybrid_rerank` 没有提高 Hit@5/MRR@5，事实覆盖与引用准确率反而略低；P95 达到 10.47 秒。原因包括：

- 语料只有 27 个切片，RRF 已把黄金证据排到前面，重排空间很小。
- Cross-Encoder 推理成本远高于一次小规模双路召回。
- 重排后的证据组合会改变 DeepSeek 的生成与引用选择，最终质量不是单调函数。

结论不是“重排无用”，而是它应在更大语料上重新评估，并通过模型常驻、批处理或条件路由降低成本。

## 8. 已知失败与限制

- 结果不是 100%：部分本可回答问题被 Grounding Policy 拒答，复杂回答也可能漏事实或多引证据。
- 事实覆盖采用确定性的参考事实匹配，适合本次冻结语料，但不能代替人工语义审查。
- 未启用未实测的 NLI 真值模型；报告不虚构 NLI 分数。当前依据是黄金事实、稳定证据 anchor 与引用校验。
- 30 条用例、3 个文件不足以代表生产分布；没有覆盖 OCR、表格、文档冲突、版本过期和恶意提示注入。
- DeepSeek 输出存在自然波动；报告记录实际模型、时间和 Git commit，复跑数值可能小幅变化。

## 9. 复现实验

先按 [RUNBOOK](RUNBOOK.md) 启动 Qdrant、准备 DeepSeek Key 并入库冻结语料，然后执行：

```bash
PYTHONPATH=. .venv/bin/python -m evals.run_ablation \
  --dataset evals/datasets/enterprise_30.jsonl \
  --provider deepseek \
  --model deepseek-v4-flash \
  --embedding-profile st_bge_large_zh \
  --output evals/reports/final
```

运行器逐条记录失败，不会跳过；四组实验必须全部完成后才比较结果。若调整阈值或参数，应一次只改一个变量，再完整重跑 120 次并生成新的冻结报告。
